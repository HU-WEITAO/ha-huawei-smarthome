- 实机确认包含灯光开关／调光／色温、窗帘和梦幻帘、温湿度读数、热水器统计与控制、马桶、浴霸、除湿机及 AI 后续设置。用户也确认扫地机器人此前已测。本次整理不再触发重复实机测试，不把这次离线回归说成新一轮实机验证。
- 当前离线测试验证明确的 payload、未知／无效状态、缩放、命令顺序、失败中止、并发设置保留，以及真实 HA 平台实体的构造。

## 关键行为

### 灯具

亮度在设备百分比和 HA 的 0–255 之间转换；色温遵守具体 Profile 的范围和步长。多字段命令先校验，再依序发送电源、亮度、白光模式（ZG0O）、色温；某一步失败时不继续。ACK 不修改读回状态。

ZG0O 的 Profile 同时包含彩色控制，但本次只提供已验证的白光能力。该控制器也可能连接物理单色灯带：即使回报色温，灯带也可能不支持变色温。集成没有可靠字段区分外接灯带种类，因此依 Profile 暴露控制器的色温能力，不按用户设备 ID 隐藏功能。未提供未经验证的 RGB。

### 窗帘

140B / 2N5R 使用已确认的 0=全关、100=全开。27WB 的位置方向未确认，因此不会把原始位置转为 HA 开度或推断关闭状态；开、关、停仍可独立使用。

### 热水器、马桶和浴霸

- 2GIP 的 `totalWater.current`、`totalGas.current`、`curWater.current` 除以 10；单位分别为吨、立方米、升。
- 2N91 盖板和座圈呈现为按钮，每次按键根据最新回报切换对应控制位，保留实测命令行为；状态未知时拒绝猜测。冲水与停止也为按钮。清洗／烘干仍受设备着座保护，未着座不响应不是 HA 命令失败。
- 29UZ 的 `Switch.on1=1` 表示待机。提供明确的“待机”按钮，不包装成普通总电源切换；实测待机会停止吹风，保留照明。
- 若曾安装非公开本地版本，按钮与旧 switch 的实体类型／唯一 ID 可能不同；本次没有修改既有上游型号的实体 ID。迁移私人仪表盘需单独处理。

### AI 传感器

仅匹配 ZG0F，不直接复用 ZG1Y 的电源语义。高级位掩码的 bit 0 为抗干扰、bit 5 为防宠，bit 25 为防宠能力。写入只改目标位，保留其他位；在前次目标值被设备回报前拒绝继续改同一组合配置。区域响应同样保留 16 项列表中的其他区域配置，配置已改变时拒绝旧控制。

区域与坐标作为 sensor 附加属性提供；本 PR 不包含地图卡片。`coordinate_system=vendor_xy` 表示厂商坐标，不能直接当作米。`position_received_at` 初始为 null，仅在收到 `positionList` / `postionList` 时记录当前接收时间；普通有人事件不会刷新旧坐标。前端应结合 `position_valid`、`report_mode`、时间戳和 `freshness_seconds=15` 判断是否显示实时位置。

不提供区域绘制／编辑、华为 App 历史记录或恢复出厂等操作。位掩码尚未上报时不创建对应设置实体；首次回报后可重载集成以发现这些实体。

## 单品适配器与平台依赖

- 21 个 `prod_<prodId>.py` 均独立实现服务映射、读取换算、校验与命令，不依赖其他单品适配器或新增公共辅助实现。各型号仅依赖既有 `api.EntitySpec`。
- 字段和命令由各文件明确声明；Profile 仅用于核对该型号字段的权限、范围、步长和枚举，不扫描任意字段生成实体。
- ZG0F 的几何解析、位掩码、区域响应实现全部位于 `prod_ZG0F.py`。
- 本适配器 PR 不修改 `cover.py`、`humidifier.py`、`sensor.py`。平台元数据支持及独立测试见 [实体工厂 PR #134](https://github.com/xiasi0/ha-huawei-smarthome/pull/134)。
- 基础实体和控制可在既有平台工厂下工作；窗帘/除湿机的 `device_class`，以及 ZG0F 的区域坐标附加属性和字段接收时间戳，需要实体工厂 PR 合并后才会在 HA 中呈现。建议先合并实体工厂 PR；实体工厂本身不依赖这 21 个适配器。

## 运行回归测试

只测试协议层（无需 Home Assistant，1 项 HA 实体构造测试会跳过）：

```bash
python3 -m unittest discover -s tests -v
```

在安装了 Home Assistant 及本集成依赖的 Python 环境中运行相同命令，会额外检查真实 HA 实体及监听器生命周期。当前验证环境：Home Assistant 2026.9.3 / Python 3.14。

`tests/fixtures/verified_profiles.json` 只包含这些测试使用的公开字段、枚举和约束；所有状态、区域名和坐标均在测试中合成，没有完整 Profile 或真实家庭快照。
